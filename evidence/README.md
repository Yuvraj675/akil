# AKIL evaluation evidence

Everything in this folder is generated by one command:

```bash
python3 scripts/run_evidence_simulations.py
```

The run takes 1–2 minutes. It requires Go to be installed for the hardware overhead benchmarks.

## What is simulated, modelled and measured

| Part | Status | How |
|---|---|---|
| Pod placement | **Simulated** | 10 seeds × 50 epochs × 15 arrivals on five 2-core nodes. The AKIL scorer is a line-for-line port of `pkg/scoring/scorer.go` (corrected cache term: neighbour's rate), combined with `LeastAllocated` at plugin weight 25 (`deploy/kubernetes/scheduler-config.yaml`). |
| Latency, LLC miss rate | **Modelled** | Derived per web pod from the neighbours it was actually placed with. Interference coefficients are grounded in empirical microarchitectural literature: Heracles [Lo et al., ISCA 2015] Fig. 5 (LLC degradation), PARTIES [Park et al., ASPLOS 2019] Table 3 (lock contention), and Ubik [Kasture & Sanchez, ASPLOS 2016] §5 (memory-bus contention). |
| Scoring overhead | **Measured** | Go benchmarks: `BenchmarkScore` (scorer maths) and `BenchmarkScoreQueries` (real gRPC queries to the in-memory aggregator over loopback on an Intel Core i5-13500H). |
| Live-cluster latency and placement | **Measured** | `deploy/experiment/run.sh` on a 4-node kind cluster, real stress-ng neighbours, then `scripts/summarize_live_runs.py`. |
| eBPF overhead, collector footprint, ingest rate | **Not measured** | Future work on bare-metal clusters. |

## Headline results (mean ± 95% CI, 10 seeds)

| Configuration | Web pods next to cache-stress | LLC miss % | p50 ms | p99 ms | SLO violations % | Node Ctx Switch (/s) |
|---|---|---|---|---|---|---|
| Isolated (oracle) | – | 38.0 | 9.44 ± 0.01 | 17.53 ± 0.05 | 3.6% | 2,500 |
| Default K8s | 36.0% | 50.0 ± 0.6 | 17.43 ± 0.81 | 62.68 ± 4.58 | 61.8% | 11,248 ± 336 |
| BinPacking | 88.2% | 81.6 ± 1.2 | 128.41 ± 6.09 | 260.60 ± 6.44 | 98.1% | 51,714 ± 1,137 |
| Trimaran-TLP | 83.9% | 79.0 ± 1.3 | 114.45 ± 7.11 | 254.58 ± 8.49 | 97.3% | 48,158 ± 1,227 |
| **AKIL** | **28.4%** | **49.0 ± 0.5** | **16.17 ± 0.40** | **49.74 ± 1.46** | **57.9%** | **10,060 ± 210** |

### Key takeaways:
- **Vs. Default K8s:** AKIL reduces dangerous co-location with cache-stress from 36.0% to 28.4% (a 21.1% relative reduction). This yields a **20.6% reduction in p99 tail latency** (62.68 ms → 49.74 ms, non-overlapping 95% CIs), reduces context-switch load by 10.6%, and improves SLO violations from 61.8% to 57.9%.
- **Vs. BinPacking & Trimaran-TLP:** Density-oriented (`MostAllocated`) and coarse CPU utilization-aware (`Trimaran TargetLoadPacking`) schedulers pack workloads densely without visibility into microarchitectural thrashing. They co-locate web pods with cache-stress in 84–88% of cases, resulting in catastrophic tail latency (>250 ms, >97% SLO violations). AKIL prevents this tail latency collapse entirely (>80% lower p99).

**Measured overhead per `Score()` call** (i5-13500H):
- Scoring maths: 49 ns (1 pod) to 1.87 µs (100 pods).
- Aggregator gRPC queries: 0.29 ms (1 pod) to 0.54 ms (100 pods) over loopback.
- Well within the Kubernetes 5 ms scheduling budget.

## Live-cluster measurement (measured, not modelled)

| Placement | n | p50 ms | p99 ms |
|---|---|---|---|
| Pinned, alone | 3 | 6.4 ± 0.4 | 9.2 ± 1.2 |
| Pinned, next to lock-stress | 3 | 6.8 ± 0.3 | 15.0 ± 5.4 |
| Pinned, next to batch-worker | 3 | 11.5 ± 2.9 | 23.7 ± 4.6 |
| Pinned, next to cache-stress | 3 | 9.4 ± 2.5 | 24.6 ± 22.9 |
| Default scheduler (cache-stress node 10/10) | 10 | 9.0 ± 0.3 | 19.3 ± 2.0 |
| AKIL (batch-worker node 9/10) | 10 | 11.0 ± 1.2 | 22.8 ± 3.2 |

AKIL detects and avoids the under-declared cache thrasher, but with the default weights it picks the page-fault-heavy node, which hurts this service as much. **The simulated latency gain is not reproduced on this testbed.** See paper Sec. "Live-Cluster Measurement".

```bash
deploy/experiment/setup.sh              # once
deploy/experiment/run.sh 10 30          # ~25 min
python3 scripts/summarize_live_runs.py
```

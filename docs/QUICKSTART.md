# Quickstart Guide

This guide provides step-by-step instructions for running the AKIL cluster locally, demonstrating the telemetry pipeline, and cleaning up the environment.

## Prerequisites
Ensure you have the following installed and available in your system's `PATH`:
- `docker`
- `kind` (Kubernetes in Docker)
- `helm`
- `kubectl`
- `go` (version 1.22+)
- `make`

---

## 1. Deploy the Cluster
AKIL is fully automated for local deployment using a bash script. The script builds the binaries, creates a `kind` cluster, builds and loads the Docker images, deploys the Helm charts, and starts the benchmark workloads.

Run the deployment script from the root of the project:
```bash
./run.sh
```

**What this does:**
1. Verifies all dependencies.
2. Compiles the Go binaries (`collector`, `aggregator`, `akil-cli`, `akil-scheduler`).
3. Provisions a `kind` cluster named `akil`.
4. Deploys the AKIL Helm chart into the `akil-system` namespace.
5. Deploys synthetic workloads (`cache-stress` and `lock-stress`) into the `default` namespace.

*Note: If the script fails at any point, it will automatically tear down the partial cluster to leave your environment clean.*

---

## 2. Demonstrate the Project
Once `./run.sh` succeeds, it will leave the cluster running. You will need three separate terminal tabs to fully demonstrate the end-to-end functionality.

### Terminal 1: Port-Forward the Aggregator
The Aggregator service runs inside the Kubernetes cluster. To allow the CLI monitor and the Scheduler simulator to access it from your host machine, you must port-forward the gRPC service.
```bash
kubectl port-forward svc/akil-aggregator -n akil-system 50051:50051
```
*(Leave this terminal running)*

### Terminal 2: Live Telemetry Monitor
Use the `akil-cli` tool to query the Aggregator in real-time and observe the sliding-window profile of the synthetic workloads.
```bash
./bin/akil-cli --workload "default/Deployment/cache-stress" --watch
```
You should see the `CACHE MISSES/s` metric actively updating based on the synthetic data generated by the collectors.

### Terminal 3: Scheduler Plugin Simulator
Run the standalone Scheduler simulator. This binary mocks the behavior of the Kubernetes scheduler by querying the Aggregator for live metrics and assigning a scheduling score to candidate nodes.
```bash
./bin/akil-scheduler --aggregator-addr=127.0.0.1:50051
```
You will see the simulator output its scoring decisions, penalizing nodes based on the telemetry it retrieved from the Aggregator.

---

## 3. Teardown and Cleanup
When you are completely finished with your demonstration or development session, use the stop script to destroy the cluster and clean up all Docker containers.

```bash
./stop.sh
```
*(This is equivalent to running `make kind-down`)*
